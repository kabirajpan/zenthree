# Documentation

## Purpose

Use this Skill when documenting behavior, setup, architecture, APIs, or contribution workflows.

## Workflow

1. Identify the audience, purpose, scope, and source of truth.
2. Inspect the current implementation and existing documentation conventions.
3. Explain observable behavior, prerequisites, workflows, and limitations accurately.
4. Include focused examples that do not encode assumptions as universal rules.
5. Keep terminology, links, and instructions consistent.
6. Review documentation against the current implementation.

## Rules

- Do not document behavior that was not verified.
- Do not expose secrets, private data, or unsafe operational details.
- Prefer concise, maintainable documentation over duplication.
- Mark platform-specific behavior and dynamically discovered project details clearly.
